# 部署与常驻（技术设计 §4.7 / §9）

电台的守护进程设计目标是 24/7 常驻。本机验证阶段与未来服务器部署的两种形态如下。

## 一、本机常驻（Windows）

### 手动启动（日常开发/验证）

```bash
pnpm dev:station     # 守护进程 :9730（tsx watch：改代码自动重启）
pnpm dev:web         # 面板 :9731
```

### 开机自启 + 崩溃自动重启（任务计划）

用 Windows 任务计划创建「登录时启动」任务，指向一个守护脚本：

```powershell
# scripts/run-station.ps1 已提供。注册任务（一次）：
schtasks /create /tn "MengkeRadio" /tr "powershell -ExecutionPolicy Bypass -File D:\...\ambient-radio\scripts\run-station.ps1" /sc onlogon /rl highest
```

`run-station.ps1` 的职责：
1. 切换到仓库根目录
2. 启动 `pnpm start`（station 的生产运行，tsx 直跑，无 watch）
3. 循环检测进程存活：崩了 3 秒后自动重启（技术设计 §4.7「崩溃自动重启」）
4. 日志写入 `data/station.log`

> 说明：任务计划是「登录时启动」而非「开机启动」——本机验证阶段避免无头后台进程；真正需要无人值守时改用「开机启动」+ 系统服务。

## 二、Docker 部署（服务器，技术设计 §9 承诺）

代码零改动迁移（core 零 IO、配置外置、SQLite 单文件、ffmpeg 装镜像）。

```bash
# 部署前
pnpm scan                          # 曲库入库（或启动时自动扫）
docker compose up -d               # station + web + 可选 caddy
```

镜像要点（部署时落地）：
- `station`：Node 22 + Python 3.11（edge-tts）+ ffmpeg；`pnpm start` 作为入口
- volume：`config/library`（曲库）、`data/`（SQLite）、`config/`（persona/config）、`.cache/`（TTS 缓存）
- 密钥：`DEEPSEEK_API_KEY` 走环境变量（.env 不入镜像）
- 健康检查：`/api/health`；崩溃由 Docker 重启策略兜底
- **公网前必做**：admin 台加访问 token（当前单机版无鉴权，FR-100 依赖「仅本机访问」）
